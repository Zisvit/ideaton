# UX: язык продукта

Аудитория: студенты колледжа 2–4 курса, куратор, жюри хакатона.
Правило: говорим **как с наставником в кабинете**, не как как система оценки.

## 1. Пять ролей — по одной фразе

| Роль | Фраза для интерфейса |
|---|---|
| **Студент** | «Ты в самом начале — это нормально, сейчас разберёмся» |
| **Куратор** | «Ты за месяц сделал X — вот где это видно» |
| **Работодатель / партнёр** | «Смотрю, кто уже умеет делать вот это» |
| **Преподаватель** | «Класс в целом готов, осталось двое — вот их карточки» |
| **Жюри хакатона** | «Смотрю не на оценку, а на то, что реально сделано» |

Формула: **что сделано → что дальше**. Никогда «что не умеешь» (см. §4).

## 2. Пустые состояния

Пустой экран — не ошибка, а первый шаг. Всегда: короткая фраза + пример + одна кнопка.

| Экран | Текст | Кнопка |
|---|---|---|
| Нет профиля | «Пока пусто. Начни с одного проекта — это 5 минут» | «Добавить первый проект» |
| Нет оценок | «Оценок пока нет. Раздел откроется, когда куратор посмотрит проект» | «Попросить разбор» |
| Пустой топ | «Пока никто не опубликовал проекты. Будь первым — твой проект попадёт сюда» | «Опубликовать проект» |
| Нет пробела-маршрута | «Маршрут соберётся, когда появятся оценки. Пока можно посмотреть примеры» | «Посмотреть примеры» |
| Поиск ничего не нашёл | «Ничего не нашлось. Попробуй имя или навык покороче» | «Очистить поиск» |

Правила: без слова «Ошибка», без заглавных букв в начале фразы-объяснения, без «данных нет». Одна кнопка — одна главная.

## 3. Карточка пробела — что показываем

Не «уровень 2 из 5», а маршрут:

1. **Название** — «Что прокачать» (не «Дефицит компетенций»)
2. **Зачем это** — одна строка: «Без этого не берут на стажировку по фронту»
3. **Маршрут из 3 шагов** — обязательно с конкретикой: «SQL → docker-compose → деплой»
4. **Сколько займёт** — «~2 недели по 4 ч в неделю»
5. **Кто проверит** — «куратор Аня, после 3 проектов»

Каждый пробел обязан давать маршрут. Пробел без маршрута — это ярлык «ты плохой». Не показываем.

## 4. Мягкие формулировки пробелов

| Не пишем | Пишем |
|---|---|
| «Чего не умеешь» | «Что изучить» |
| «Дефицит навыков» | «Следующий шаг» |
| «Не соответствует требованиям» | «Для этого нужно ещё» |
| «Пробел» (в требовании) | «Маршрут» |
| «Слабый уровень: 2/10» | «Базовый уровень — есть база, идём дальше» |
| «Не готов к работе» | «Уже на пути, осталось 2 шага» |
| «Ошибка: нет данных» | «Пока пусто — это начало» |

Запрещено: красный, «❌», «провален», «слабый», «не умеешь» — в любом виде, включая тултипы и подписи графиков.

## 5. Дисклеймеры

Один и тот же текст, в трёх местах: первый заход, экспорт резюме, печать.

> Это не трудоустройство. Карьерный трекер показывает, что вы уже умеете и что можно прокачать — решение о найме принимает работодатель сам. Данные не передаются третьим лицам.

Короткая версия для футера: «Помогаем собрать портфолио, не трудоустройство.»

Дисклеймер **виден до первого результата**, а не спрятан в подвал. Один раз показали — дальше не мешает.

## 6. Тон ответов

- Ты/вы — «ты». Обращение на «вы» = ощущение бюрократии.
- Ошибка → что сломалось + как починить, в одно предложение. «Не нашли — попробуй короче».
- Нет вины. Оценка — про навык, не про человека.
- Максимум 2 предложения на экран. Длинный текст = не прочитали.
- Числа — с контекстом: не «60%», а «6 из 10 проектов закрыто».
- Никаких восклицательных знаков. «Молодец» — ок, «ТЫ МОЖЕШЬ!» — нет.
- Успех: «Готово. Топ-5 обновился» вместо «Поздравляем!!!».

## 7. Холодный старт

Риск №1. Правила первого 3 минут:

- Первый экран: **пример**, а не пустой инпут. «Вот как выглядит заполненный проект — повтори за 5 минут».
- Кнопка «Заполнить примером» — профиль собирается за один клик, дальше можно переписать.
- Демо-данные в первый вход, не в сервере.
- Не спрашивать всё сразу. Максимум 3 вопроса за сессию, остальное — потом.
## 8. Живая база — шедевр в сценах (v5)

Заказчик: «моушн-дизайн должен быть везде и повсюду». Совет конвертировал
запрос в бюджет: движение **живёт на всей поверхности**, но у каждого движения
есть причина (отклик или вход). Правило §8: **движение оправдано, когда оно
кодирует изменение состояния или направляет порядок чтения; остальное —
декорация, и её убирают.**

Токены — единственный источник таймингов (no magic numbers):
`--m-fast 120ms` (hover/press/focus) · `--m-base 220ms` (реакция/мин) ·
`--m-slow 350ms` (вход секций) · `--m-sheen 400ms` (блик, once) ·
stagger `50ms`, cap 8 шагов (окно входа ≤ 400 ms). Easing: `--ease` (база),
`--m-ease-inout`, `--m-ease-back` (пружина, только transform).

**Разрешено повсеместно**

- Микро-отклики на hover/press/focus: 120 ms, transform-only (чипы, кнопки,
  карточки, чекбоксы).
- Вход карточек/строк/секций: fadeIn-лесенка со stagger 50 ms, cap 8
  (`.stagger`, flat-cap `:nth-child(n+8)`).
- State-попы при изменении состояния: галочка-чекбокс, «Разобрался»,
  верный choice (mPop 220 ms, пружина) — без красного и без счёта.
- Блик CTA (.btn-primary::after, sheen 400 once, только в hover:hover).
- Три бесконечных цикла — ТОЛЬКО сцены: (1) фон v5 = aurora 4 блоба (36s,
  ±2.5%) + dot-grid (18s, 24px) + 3 микро-фигуры (36–42s, ≤ 4 px/s), одна
  палитра бренда; (2) интро 4.2 s: лис пробегает (диагональный галоп,
  4 сустава ног), прыжок-squash на знак, пыль, импульс и блик знака
  (2160–3060), дыхание/idle до вуали; (3) конфетти плана.
- Loader консультанта (bounce) — существующий, единственный бесконечный
  цикл на контенте; текст состояния остаётся читаемым при reduced-motion.

**Запрещено**

- Анимация layout-свойств: width/height/top/left/right/bottom/margin/
  padding/font-size/letter-spacing (гейт `test_motion_css` ловит все).
- Paint-свойства в `@keyframes`: box-shadow, filter, background-position
  (блик на бумаге — не «исключение»: markSweep v5 — transform-шиммер).
- Мигание > 3/с и полнокадровые смены яркости (WCAG 2.3.1).
- Бесконечные циклы на элементах контента (кроме loader), авто-играющие
  анимации на полях ввода.
- Маскирование пустых состояний движением; JS-моушн (rAF-tilt) —
  отклонён советом (3:2): не глушится единственным контрактом reduced-motion.
- Потолок: всё длиннее 400 ms живёт только в трёх сценах.

**Глушители и контракты**

- `prefers-reduced-motion` — один глобальный `animation/transition: none
  !important` (v3) гасит ВСЁ; сцены к тому же не монтируются JS-гейтом.
- Print: `animation/transition: none`, сцены display:none, зачёркивание
  задач на бумаге — статичное `line-through` (v5-блок в MUTE).
- Append-only для базы: селекторы v1–v3 не правятся; сцены и микро меняются
  хирургически в хвостовом блоке. Бюджет: `@keyframes` ≤ 30 имён на файл
  (проверяет `tests/test_motion_css.py`).
- IntersectionObserver-reveal НЕ вводим (deepseek): страницы демо короче
  экрана, а три режима отказа (print, reduced-motion, фолд) реальны.

Вуза-бренд: интро рисует **проектный знак и талисмана проекта** (лис «Идея»
208 px / 176 px на мобиле — дискретные ступени, не clamp), не «официальный
логотип СИУЭиП» (брендбука в репо нет). Не имитировать эмблемы и гербы.

## 9. Волна v6: мини-проверки · скрипт-консультант · fx-декор

**A. Мини-проверка у каждого пункта плана** («понял ли», no-score)

- Генерация на фронте (`lib/planChecks.ts`): префиксы задач → тип CHOICE
  («зачем навык», gap-пункты), SELF («объясни одной строкой + ориентир»),
  DO («сделал, могу показать»). Навык вне глоссария → теста нет (no-signal:
  нет кнопки — нет обещания).
- UI: чип-строка «Проверить» (min-height 44) под пунктом; открытие —
  grid-template-rows 0fr→1fr, 220 ms (единственное layout-исключение волны,
  допущено советом и ограничено одним селектором в гейте). Аккордеон:
  открыта ровно одна, закрытие предыдущей мгновенно. Слоты подсказки
  (22 px) и статуса (24 px) резервируют высоту ⇒ CLS = 0.
- Неверный выбор в CHOICE — не красный, а строка «как это записано в базе»;
  повтор безлимитный. Хранение отдельно от done: `career-tracker-mini:v1:{role}`
  (мини-тест не двигает галочки «сделал»). Печать: мини-строки не печатаются.

**B. Консультант на заготовленных скриптах** (до подключения API)

- `USE_LIVE_CHAT = false` — флаг будущего включения /chat; страница не делает
  ни одного сетевого вызова (гейт `test_v6_consultant_scripts`).
- 7 тем + guard: «с чего начать / не знаю что умею / какая роль / план /
  портфолио / наставник не смотрит / «не получится»»; каждая тема завершается
  действием (CTA «Открыть план → неделя 1» или ≥ 2 follow-up-чипов).
- Свободный текст → keyword-матч (longest-substring, словари 6–12 слов с
  разговорными оборотами). Guard-зёрна (зарплата/трудоустройство/парс
  вакансий/«двойник») перехватываются ДО матчинга и ведут в честную памятку:
  «не обещаем трудоустройство, оффер и зарплату; не парсим вакансии».
  Ничья ключей → честный «miss» со списком тем, не выдумка.
- Бейдж «скриптовый режим» + подпись «текст не уходит в сеть»; лис-мини
  44×36 — талисман ПРОЕКТА (не носитель статуса). Строки входят в DOM сразу,
  лесенка fadeIn с шагом 70 ms (cap 8) — без JS-тайпинга.

**C. fx-декор «сносит головы» в рамках §8**

- Бюджет анимаций: НОВЫЙ keyframe ровно один — `foxMiniBlink` (29 → 30/30
  свободного слота гейта; выбран советом из-за «мёртвого окна» траты v5-blink
  на длинных периодах). Всё остальное — реюз (fadeIn/mPop/bounce/breath/
  tailIdle) и transitions. Гейт `≤ 30` не правился.
- Conic-рамка: РОВНО ОДИН оборот transition 12 s linear на карте навыков
  index (`.is-swept` после интро; `is-swept-done` отпускает слой). Не keyframe,
  не бесконечность; result и план остаются статичными. Paint-traps запрещены
  везде (гейт ловит `backdrop-filter`, `mix-blend-mode`, `@property`).
- Шум-плёнка: запечённая плитка `public/noise-64.png` (64×64, палитровый PNG
  с alpha, ≤ 8 KB, 643 B фактично; генератор `scripts/gen_noise.py`) вторым
  бэкграундом `.fix-bg` — alpha в пикселях (CSS opacity не промоутит слой),
  без blend, не поверх контента.
- Стекло-блик: статичная 1 px световая полоса (site-header/cta-bar/бот-баббл);
  backdrop-filter не используется (paint-трэп при скролле). Бренд-градиент
  заголовков (`.grad`) — статичный, распространён на result/plan/consultant.

Доки демо: см. `docs/DEMO.md` — сценарий 90-секундки дополнен мини-проверкой
и двумя ветками консультанта.

## 10. Волна v7: 21 специальность · лимит 1–12 · «Карта тем»

**A. Одна закрытая база — 26 направлений.**

- `data/roles/*.yaml`: 5 карьерных ролей (`kind: role`) + 21 специальность
  СИУЭиП (`kind: specialty`, 4+ навыка и 5 шагов у каждой). Каталог
  специальностей не дублирует «Цифрового двойника студента», не парсит
  вакансии и не обещает трудоустройство/оффер/зарплату — только маршрут.
- `POST /recommend` принимает `limit` 1..12 (дефолт 12): `rows[:limit]`,
  fallback тоже режется, кэш включает limit. Контракты в lockstep:
  `openapi.yaml` (RoleId = 26, `limit`, `RoleScore.kind`) и
  `roles.schema.json`; гейт `test_v7_specialties.py` сверяет словари.
- CHOICE-дистракторы в API берутся из того же `kind` — специальности не
  «подмешивают» карьерные роли в варианты друг друга.
- `/result`: заголовок «Твои направления», на первом экране 5 карточек,
  кнопка «Показать все N направлений» раскрывает до 12; чип `роль` /
  `специальность`; у специальностей акцент считается по хэшу id (26 карточек
  различимы, новых CSS-переменных не заводим).
- `/` (index): второй ряд чипов — 8 не-IT сфер (Уход, Бухучёт, Право,
  Педагогика, Дизайн, Электромонтаж, Сети, Торговля). Каждый чип — точный
  синоним из `skills.yaml`, поэтому участие в скоринге настоящее, а не декор.

**B. Глоссарий 89 тем и честные мини-проверки.**

- `apps/web/lib/glossary.json`: 87 навыков каталога + `api` + «учебный
  проект»; поля `name/cluster/aliases/why/what/hint`, у малых кластеров —
  явные `distractors`. Доступ через `GLOSSARY` в `planChecks.ts`.
- Резолвер темы: нормализация (lowercase, ё→е) + самое длинное вхождение
  алиаса. Каждый шаг каждой специальности резолвится в навык из
  `skills_required` своей роли — это гейт, а не пожелание: python-зеркало
  генератора в `test_v7_specialties.py` повторяет регулярки и резолв.
- Дистракторы — соседи по кластеру (у legacy-тем явные), верный ответ
  выбирается детерминированной ротацией по хэшу промпта: не всегда первый
  вариант. Гейт проверяет 3 различных варианта и ≥2 позиции верного.
- No-score без изменений: нет счёта, нет красного, повтор безлимитный;
  подсказка — «как это записано в базе», а не «неправильно».

**C. «Карта тем» — мини-граф Obsidian на `/plan`.**

- `lib/topicGraph.ts` — чистый детерминированный полярный layout: центр —
  направление, 4 луча — недели (сверху по часовой), темы — на внешнем
  кольце вокруг своего луча. Рёбра: `week→topic` и `topic↔topic` по общему
  навыку (`MiniCheck.skill`). Без библиотек, без случайности.
- `components/TopicMap.tsx`: SVG-рёбра (`vector-effect="non-scaling-stroke"`)
  + HTML-кнопки-узлы (клавиатура, `focus-visible`, `aria-pressed`, тач-зона
  44 px). Узлы = пункты плана (`taskKey` общий с чекбоксами).
- Клик по теме открывает панель с тем же интерактивом, что в аккордеоне:
  `MiniCheckBody` вынесен из `MiniRow` и переиспользуется; «Открыть в плане →»
  раскрывает аккордеон и скроллит к пункту (`prefers-reduced-motion` →
  мгновенный скролл).
- §8 соблюдён: 0 новых `@keyframes` (30/30), бесконечностей нет, RM-гейт
  глушит transitions универсальным правилом, карта не печатается
  (`plan-print-hide` + print-блок), сам план на бумаге статичен.
- Инфра: Docker-контекст API — корень репозитория, `data/roles` копируется
  в образ, `ROLES_DIR=/app/data/roles`; иначе контейнерный стенд молча
  отдавал бы встроенный дефолт из 5 ролей.
